# რეგისტრაცია და შესვლა ელფოსტით (Supabase)

ეს არჩევითი შესაძლებლობაა. ჩართვის შემდეგ `/register` ითხოვს სახელს, ელფოსტასა და პაროლს (დასადასტურებელ წერილს Supabase აგზავნის), `/login` კი ელფოსტასაც იღებს. **სკოლის საკუთარი ანგარიშები (სახელი და პაროლი, მასწავლებლები, დემო) უცვლელად მუშაობს**, ისევე როგორც სახელით რეგისტრაცია (ის ფორმის ქვემოთაა, „ელფოსტა არ გაქვს?“). თუ ცვლადები არ არის მითითებული, საიტი ისე მუშაობს, როგორც ადრე, ინტერნეტის გარეშეც.

## რა ხდება ეკრანის უკან

1. ბრაუზერი `@supabase/supabase-js`-ით ეძახის Supabase-ს (`signUp` ან `signInWithPassword`). ბრაუზერი **არაფერს ინახავს** (არც localStorage, არც ფონური განახლება): საერთო კომპიუტერზე მომდევნო მოსწავლეს წინა მოსწავლის ტოკენები არ დარჩება.
2. თუ პროექტი ელფოსტის დადასტურებას ითხოვს, მომხმარებელი ხედავს „შეამოწმე ელფოსტა“ და წერილის ბმულს ხსნის. ბმული `/auth/callback`-ზე აბრუნებს; იქ მისამართიდან ტოკენი იკითხება და მაშინვე იშლება მისამართის ზოლიდან და ისტორიიდან.
3. სერვერი `POST /api/auth/supabase/session`-ით ტოკენს **თავად ამოწმებს Supabase-თან** (`auth.getUser`): ბრაუზერის ნათქვამი არ სჯერა. მხოლოდ დადასტურებულ ელფოსტას ეხსნება სესია.
4. სერვერი პოულობს ადგილობრივ ანგარიშს Supabase-ის მომხმარებლის ნომრით (ელფოსტით ან სახელით **არასოდეს**, რომ რეგისტრაციით ვინმეს არსებული ანგარიში ვერ დაეპატრონოს). თუ ანგარიში არ არსებობს, იქმნება **მოსწავლის** ანგარიში (მასწავლებელი ამ გზით არასოდეს იქმნება) და იწყება ჩვეულებრივი სერვერული სესია. თუ `SELF_REGISTRATION=false`, შედიან მხოლოდ უკვე არსებული ანგარიშები.

ეკრანზე ჩანს მხოლოდ შეყვანილი სახელი; ელფოსტა თანაკლასელებს და მასწავლებლებს არ უჩანს (ის თვითონ ანგარიშის გვერდზე ჩანს).

## ჩართვა

1. Supabase → **Project Settings → API**: დააკოპირეთ პროექტის URL და **anon / publishable** გასაღები.
2. ჩაწერეთ `.env.local`-ში (ლოკალურად) ან გარემოს ცვლადებში (Render → Environment):

   ```text
   NEXT_PUBLIC_SUPABASE_URL=https://თქვენი-პროექტი.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=...
   ```

   ორივე მნიშვნელობა საჯაროა (მათ ყველა ბრაუზერი იღებს). **service_role / secret გასაღები აქ არასოდეს ჩაწეროთ**: საიტი მას ამოიცნობს და ელფოსტით შესვლას არ ჩართავს. სერვერი ცვლადებს გაშვებისას კითხულობს, ამიტომ მათი შეცვლა თავიდან აგებას არ საჭიროებს, მხოლოდ გადატვირთვას.
3. Supabase → **Authentication → Sign In / Providers → Email**: ჩართეთ Email, ჩართეთ **Confirm email** (რეკომენდებულია: წინააღმდეგ შემთხვევაში ნებისმიერი ადამიანი ნებისმიერი მისამართით ერთბაშად შეძლებს რეგისტრაციას) და მინიმალური პაროლი დააყენეთ 8 სიმბოლო (ფორმაც 8-ს ითხოვს).
4. **Authentication → URL Configuration**: *Site URL* იყოს თქვენი საიტის მისამართი, *Redirect URLs*-ში კი დაამატეთ `https://თქვენი-საიტი/auth/callback` (დეველოპმენტისთვის `http://localhost:3000/auth/callback`). თუ მისამართი სიაში არ არის, ბმული Site URL-ზე მოხვდება: საიტი მას მაინც გადაამისამართებს `/auth/callback`-ზე, მაგრამ არასწორი Site URL (მაგალითად, `localhost`) ბმულს გაფუჭებს.
5. **რეალური კლასისთვის გამართეთ საკუთარი SMTP** (Authentication → SMTP Settings). Supabase-ის ჩაშენებული ფოსტა მთელ პროექტზე სულ რამდენიმე წერილს უშვებს საათში: 16 მოსწავლის ერთდროული რეგისტრაცია ზღვარს გადააჭარბებს („დასადასტურებელი წერილი ძალიან ბევრჯერ გაიგზავნა“).
6. გაუშვით შემოწმება: `npm run supabase:check`. ის კითხულობს ცვლადებს (`.env.local`-იდანაც), ამოწმებს, რომ გასაღები სწორია და არ არის საიდუმლო, და პროექტს ეკითხება: ელფოსტის დადასტურება ჩართულია თუ არა, ღიაა თუ არა რეგისტრაცია და რომელი მისამართი უნდა დაემატოს. `npm run doctor` ამის შესახებ მოკლე სტრიქონს ამატებს.

## კონფიდენციალურობა

ელფოსტა და პაროლი ინახება **Supabase-ში, სკოლის სერვერის გარეთ**; სკოლის სერვერზე რჩება მისამართი, ეკრანზე ნაჩვენები სახელი და პროგრესი. ამიტომ, როცა ცვლადები მითითებულია, კონფიდენციალურობის გვერდი ამას ცალკე წინადადებით ამბობს. გადაწყვიტეთ, რა წესებია თქვენი მოსწავლეების ასაკისთვის (თანხმობა, მონაცემთა დამუშავების შეთანხმება Supabase-თან). მონაცემთა წაშლისას (მოსწავლის წაშლა სკოლის სისტემაში) Supabase-ის მომხმარებელი **არ იშლება**: ის Supabase-ის დაფიდან უნდა წაიშალოს (საიტს service-role გასაღები განზრახ არ აქვს).

## რა არ არის ჯერ გაკეთებული

- **პაროლის აღდგენა** („დაგავიწყდა პაროლი?“). აღდგენის ბმული ახლა ნათლად უარყოფილია და არა მოჩვენებით შესვლად. ეს შემდეგი ნაბიჯია.
- ელფოსტის შეცვლა, ანგარიშის წაშლა Supabase-იდან, შესვლა Google-ით და სხვა პროვაიდერები.
- მასწავლებლების რეგისტრაცია: მასწავლებლებს, როგორც ადრე, სკოლა ქმნის.
- ელფოსტიანი ანგარიშებისთვის „პაროლის შეცვლა“ ანგარიშის გვერდზე ცვლის ტექსტს (პაროლს Supabase ინახავს).

## ტესტები

- `npm run test` არ საჭიროებს ინტერნეტს (ცვლადების შემოწმება, შეცდომების ამოცნობა, ბმულების წაკითხვა, ანგარიშის პოვნა/შექმნა).
- `npm run test:e2e:supabase` ამოწმებს მთელ გზას ბრაუზერში **Supabase-ის იმიტაციით** (`tests/e2e-supabase/mock-supabase.mjs`): რეგისტრაცია, დასტური, შესვლა, შეცდომები, გაუქმებული ბმულები. ის არ ცვლის რეალურ პროექტს: რეალური პროექტის პარამეტრებს `npm run supabase:check` ამოწმებს.

## თუ რამე არ მუშაობს

- **ბმულზე გადასვლისას გამოჩნდა საწყისი გვერდი ან `localhost`.** Supabase → URL Configuration: Site URL და Redirect URLs (იხ. ზემოთ).
- **„ძალიან ბევრი წერილი“.** ჩაშენებული ფოსტის ზღვარია: გამართეთ საკუთარი SMTP.
- **ფორმაზე ელფოსტის ველი არ ჩანს.** ცვლადები არ არის მითითებული ან არასწორია: `npm run supabase:check` გეტყვით რა.
- **„ბმულს ვადა გაუვიდა“ მაშინვე.** ზოგი საფოსტო პროგრამა ბმულს წინასწარ ხსნის და ერთჯერადი ბმული „იხარჯება“. სთხოვეთ მომხმარებელს ბმულის ხელახლა გაგზავნა და გახსნა.
